## Что это такое

Хорошей языковой модели нужна мощная видеокарта. В ноутбуке её, скорее всего, нет, а в домашнем ПК — вполне может быть.

**locallm** — небольшая программа для Windows (`locallm-host.exe`), которая превращает этот ПК в сервер моделей:

- 🧠 **Держит в видеопамяти одну модель** и запускает её через [llama.cpp](https://github.com/ggml-org/llama.cpp).
- 🔄 **Сама переключает модели.** Попросили `gemma`, а загружена `qwen-coder`? Хост выгрузит одну, загрузит другую и ответит. Две модели никогда не делят видеопамять.
- 🌐 **Доступна с других ваших компьютеров** через [Tailscale](https://tailscale.com) — бесплатную частную сеть. Никаких портов, открытых в интернет.
- 🔑 **Пускает только по ключу.** Пользоваться ей могут только компьютеры, у которых есть ваш ключ.
- 🖱️ **Значок у часов и веб-панель.** Освободить видеокарту под игру — один щелчок; новые модели добавляются без правки файлов.

> **За ПК тоже кто-то сидит.** Хост рассчитан на обычный домашний компьютер. «Пауза» и «Выгрузить модель» в любой момент отдают видеокарту играм или монтажу.

## Как это устроено

```
  Ноутбук / Mac / другой ПК                 Windows-ПК с видеокартой NVIDIA
 ┌──────────────────────────┐             ┌────────────────────────────────┐
 │ opencode, pi, что угодно │             │ locallm-host.exe (значок)      │
 │   "model": "gemma"       │  Tailscale  │   проверяет ключ               │
 │   ключ из                │ ──────────▶ │   загружает / меняет модель    │
 │   ~/.config/locallm/     │  частная,   │              │                 │
 │   api-key                │ шифрованная │              ▼                 │
 └──────────────────────────┘             │ llama-server.exe (llama.cpp)   │
                                          │   одна модель в видеопамяти    │
                                          └────────────────────────────────┘
```

Несколько слов, которые встретятся ниже:

| Слово | Что значит |
|---|---|
| **Хост** | Windows-ПК с видеокартой и программа `locallm-host.exe` на нём. |
| **Клиент** | Любой другой компьютер (или программа), который задаёт вопросы хосту. |
| **Модель** | Файл `.gguf` с языковой моделью, например скачанный с [Hugging Face](https://huggingface.co/models?library=gguf). |
| **Видеопамять (VRAM)** | Память видеокарты. Модель должна в неё поместиться. |
| **Tailnet** | Ваша частная сеть Tailscale: все устройства, где выполнен вход в один и тот же аккаунт Tailscale. |
| **Ключ API** | Длинный случайный пароль, который хост создаёт для клиентов. |

## Что понадобится

**На ПК-хосте**

- Windows 11
- Видеокарта NVIDIA (чем больше видеопамяти, тем крупнее модели; 16–24 ГБ — комфортно)
- Свежий драйвер NVIDIA
- 20–50 ГБ свободного места под модели

**На каждом компьютере-клиенте**

- macOS, Linux или Windows
- [Tailscale](https://tailscale.com/download), вход в **тот же** аккаунт, что и на хосте
- Программа, в которой будете работать: [opencode](https://opencode.ai), [pi](https://github.com/earendil-works/pi) или любая, что понимает OpenAI API

## Часть 1 — настройка ПК-хоста

Всё это делается **один раз**, на Windows-ПК. Команды вводятся в **Терминале Windows** (правый щелчок по «Пуску» → «Терминал»).

### Шаг 1. Поставить инструменты

Скопируйте блок в терминал и нажмите Enter. Он ставит PowerShell 7, Git, Go (нужен только для сборки программы) и Tailscale:

```powershell
winget install --id Microsoft.PowerShell -e
winget install --id Git.Git -e
winget install --id GoLang.Go -e
winget install --id Tailscale.Tailscale -e
```

Потом **закройте терминал и откройте снова**, чтобы он увидел новые программы. Запустите Tailscale из «Пуска» и войдите в аккаунт.

### Шаг 2. Скачать llama.cpp

llama.cpp — движок, который и запускает модели.

1. Откройте [страницу выпусков llama.cpp](https://github.com/ggml-org/llama.cpp/releases/latest).
2. Скачайте два архива для Windows с **CUDA**: `llama-…-bin-win-cuda-…-x64.zip` и парный к нему `cudart-llama-bin-win-cuda-…-x64.zip`.
3. Распакуйте **оба** в одну папку `C:\llama\`. Должен появиться файл `C:\llama\llama-server.exe`.

### Шаг 3. Скачать модель

Модели — это файлы `.gguf`. Кладите их в `C:\models\` (можно по подпапкам).

- Ищите на [Hugging Face модели в формате GGUF](https://huggingface.co/models?library=gguf&sort=trending).
- **Простое правило:** файл должен быть на 2–4 ГБ **меньше** видеопамяти. Остаток нужен самому разговору («контексту»).
- `Q4_K_M`, `Q4_0`, `IQ3_XXS` в названиях — степень сжатия. `Q4` — хороший выбор по умолчанию.
- У моделей, которые понимают картинки, бывает второй маленький файл `mmproj-….gguf`. Скачайте и его.

### Шаг 4. Установить locallm

```powershell
cd $HOME
git clone https://github.com/strigov/strigov-locallm.git
cd strigov-locallm
pwsh -File scripts\install.ps1
```

При первой установке скрипт спросит два пути — вводите их полностью, начиная с буквы диска:

- **папка llama.cpp** — та, где лежит `llama-server.exe`, например `D:\AI\llama`;
- **папка с моделями** — где лежат файлы `.gguf`, например `D:\AI\models`.

Путь удобно скопировать из адресной строки Проводника. Enter без ответа — `C:\llama` и `C:\models`. Чтобы не отвечать на вопросы, передайте пути сразу:

```powershell
pwsh -File scripts\install.ps1 -LlamaDir 'D:\AI\llama' -ModelsDir 'D:\AI\models'
```

Что произойдёт:

- программа соберётся и скопируется в `%LOCALAPPDATA%\Programs\locallm\`;
- настройки создадутся в `%LOCALAPPDATA%\locallm\`;
- появится ярлык **«Пуск» → locallm**;
- у часов появится 🦙 **значок с ламой** (если его не видно — нажмите стрелку `˄`), а в браузере откроется **веб-панель**.

### Шаг 5. Добавить модели

В веб-панели:

1. Нажмите **«Найти .gguf и добавить модель»**. Появятся все файлы `.gguf` из `C:\models\`.
2. Нажмите **«Выбрать»** у нужной модели. Откроется редактор с предложенным именем, например `qwen-coder`.
3. *(По желанию)* Поменяйте имя. **Клиенты будут обращаться к модели именно по нему**, поэтому делайте его коротким: латинские буквы, цифры, `.`, `_`, `-`.
4. *(По желанию)* Добавьте флаги, по одному на строку. Самый полезный — размер контекста: `-c` на одной строке и `32768` на следующей.
5. Нажмите **«Сохранить»**. Модель доступна сразу, без перезапуска.

Нажмите **«Загрузить»** рядом с ней, чтобы проверить. Пока модель грузится, значок 🟡 жёлтый, когда готова — 🟢 зелёный.

> **Профили** — именованные варианты одной модели с другими флагами, например профиль `long` с большим контекстом. Профиль `long` у модели `qwen-coder` клиенты видят как отдельную модель `qwen-coder-long`.

### Шаг 6. Открыть хост для других ваших компьютеров

Хост слушает только сам ПК. Эта команда разрешает Tailscale пробросить его в ваш tailnet (права администратора не нужны, настройка переживает перезагрузку):

```powershell
tailscale serve --bg --http=8080 http://127.0.0.1:8080
tailscale serve status
```

Вторая команда покажет **адрес хоста**, примерно такой:

```
http://my-pc.tail1234.ts.net:8080
```

📝 **Запишите его** — он нужен каждому клиенту.

> ⚠️ **Никогда не запускайте `tailscale funnel`.** Funnel открывает сервис всему интернету. `serve` оставляет его внутри вашей частной сети.

### Шаг 7. Автозапуск (по желанию)

Щёлкните по значку 🦙 → **«Запускать при входе в Windows»**.

## Часть 2 — подключение других компьютеров

Это нужно сделать на **каждом** ноутбуке или компьютере, который будет пользоваться моделями. Команды ниже — для Терминала **macOS / Linux**; вариант для Windows — под каждым блоком.

### Шаг 1. Войти в tailnet

Поставьте [Tailscale](https://tailscale.com/download) и войдите в **тот же аккаунт**, что и на ПК-хосте.

Проверьте, что хост виден (подставьте свой адрес):

```bash
curl http://my-pc.tail1234.ts.net:8080/health
```

Ожидаемый ответ: `{"status":"ok"}`.

> Если пишет `Could not resolve host`: нажмите значок Tailscale в строке меню и включите **«Use Tailscale DNS settings»**.

### Шаг 2. Перенести ключ API

Хост создал ключ при первом запуске в файле `%LOCALAPPDATA%\locallm\keys.txt`. Каждый клиент хранит его в одном и том же месте: `~/.config/locallm/api-key`. Программы читают ключ оттуда, поэтому в их настройках он не появляется.

**Проще всего — через Taildrop** (отправка файлов в Tailscale). На **ПК-хосте** замените `my-laptop` на имя клиента из приложения Tailscale (двоеточие и кавычки обязательны):

```powershell
tailscale file cp "$env:LOCALAPPDATA\locallm\keys.txt" "my-laptop:"
```

На **клиенте** файл окажется в «Загрузках». Этот блок кладёт ключ на место и стирает скачанный файл:

```bash
mkdir -p ~/.config/locallm
grep -v '^#' ~/Downloads/keys.txt | head -n 1 | tr -d '\r\n ' > ~/.config/locallm/api-key
chmod 600 ~/.config/locallm/api-key
rm ~/Downloads/keys.txt
wc -c ~/.config/locallm/api-key
```

Последняя строка должна напечатать `43` — длину ключа.

<details>
<summary><b>Клиент на Windows</b> (PowerShell)</summary>

```powershell
New-Item -ItemType Directory -Force "$HOME\.config\locallm" | Out-Null
$key = (Get-Content "$HOME\Downloads\keys.txt" | Where-Object { $_.Trim() -and -not $_.StartsWith('#') } | Select-Object -First 1).Trim()
[IO.File]::WriteAllText("$HOME\.config\locallm\api-key", $key)
Remove-Item "$HOME\Downloads\keys.txt"
(Get-Item "$HOME\.config\locallm\api-key").Length
```

Если Taildrop не подходит, откройте `keys.txt` на хосте в Блокноте и перенесите длинную строку (не ту, что начинается с `#`) в файл `api-key` вручную.

</details>

**Проверка** (подставьте свой адрес):

```bash
H=http://my-pc.tail1234.ts.net:8080
KEY=$(cat ~/.config/locallm/api-key)
curl -s -H "Authorization: Bearer $KEY" $H/v1/models
```

В ответе должен быть список с именами ваших моделей. Без ключа хост ответит `401`.

> 🔐 **Не показывайте ключ.** Не вставляйте его в чаты и не коммитьте в git. Чтобы отозвать ключ, удалите `keys.txt` на хосте и перезапустите хост — появится новый ключ, его нужно заново перенести на клиенты.

### opencode

opencode не знает, какие модели есть на хосте, поэтому их перечисляют в его конфиге. Каждая запись — **имя модели в точности как в панели хоста**.

Файл конфига: `~/.config/opencode/opencode.jsonc` (на Windows — `%USERPROFILE%\.config\opencode\opencode.jsonc`).

Пример для двух моделей, `qwen-coder` и `gemma` — **замените адрес и имена моделей на свои**:

```jsonc
{
  "$schema": "https://opencode.ai/config.json",
  "model": "gpu/qwen-coder",                         // модель по умолчанию: "gpu/<имя>"
  "providers": {
    "gpu": {
      "name": "Мой ПК с GPU (locallm)",
      "package": "@opencode/ai/providers/openai-compatible",
      "settings": {
        "baseURL": "http://my-pc.tail1234.ts.net:8080/v1",   // ← адрес хоста + /v1
        "apiKey": "{file:~/.config/locallm/api-key}"         // ключ читается из файла
      },
      "models": {
        "qwen-coder": {
          "modelID": "qwen-coder",                   // ← в точности как имя на хосте
          "name": "Qwen Coder (ПК)",                 // любая подпись
          "capabilities": { "tools": true, "input": ["text"], "output": ["text"] },
          "limit": { "context": 32768, "output": 8192 }      // context ≤ -c модели на хосте
        },
        "gemma": {
          "modelID": "gemma",
          "name": "Gemma (ПК)",
          "capabilities": { "tools": true, "input": ["text", "image"], "output": ["text"] },
          "limit": { "context": 16384, "output": 4096 }
        }
      }
    }
  },
  "agents": { "title": { "disabled": true } }        // ← важно, см. ниже
}
```

На что обратить внимание:

| Настройка | Зачем |
|---|---|
| `baseURL` заканчивается на **`/v1`** | opencode говорит на OpenAI API, а он живёт по адресу `/v1`. |
| `modelID` = имя на хосте | Регистр важен: `Gemma` ≠ `gemma`. |
| `limit.context` | Не больше `-c` этой модели на хосте. Если `-c` не задавали, посмотрите столбец «Контекст» в панели. |
| **Профиль** — отдельная запись | Например, `"qwen-coder-long": { "modelID": "qwen-coder-long", … }` со своим, большим `limit.context`. |
| `"agents": {"title": {"disabled": true}}` | Без этого opencode шлёт лишний фоновый запрос, чтобы придумать название сессии. На одной видеокарте это напрасная работа, а то и смена модели. |
| Не назначайте субагентам и компакции *другую* локальную модель | Иначе хост будет менять модели посреди работы. |
| `"input": ["text", "image"]` | Только для моделей, у которых на хосте подключён файл `mmproj`. |

**Как пользоваться:** запустите `opencode` в папке проекта. Команда `/models` выбирает другую модель — хост сменит её сам. Первый ответ после смены может идти 10–60 секунд, пока модель грузится: это нормально.

### pi

В pi встроена поддержка llama.cpp, и хост говорит на её языке. pi сам **показывает, загружает и выгружает** модели на хосте.

**Войти один раз.** Сначала скопируйте ключ в буфер обмена, не показывая его на экране:

```bash
pbcopy < ~/.config/locallm/api-key          # macOS
# xclip -sel clip < ~/.config/locallm/api-key   # Linux
# Get-Content ~\.config\locallm\api-key | Set-Clipboard   # Windows
```

Затем в pi:

```
/login llama.cpp
```

- **URL:** адрес хоста **без** `/v1` — например, `http://my-pc.tail1234.ts.net:8080`
- **API key:** вставить из буфера

<details>
<summary>Вместо <code>/login</code> — переменные окружения</summary>

Допишите в `~/.zshrc` или `~/.bashrc`:

```bash
export LLAMA_BASE_URL=http://my-pc.tail1234.ts.net:8080
export LLAMA_API_KEY=$(cat ~/.config/locallm/api-key)
```

</details>

**Как пользоваться:**

| Команда | Что делает |
|---|---|
| `/llama` | Показывает модели хоста с их состоянием. Выберите модель — она загрузится. Если загружена другая, pi спросит, что делать; «выгрузить и загрузить» и «оставить и загрузить» приводят к одному и тому же: хост меняет модель. |
| `/model` | Выбрать, с какой из **загруженных** моделей разговаривать. |

Профили видны в `/llama` как отдельные имена (например, `qwen-coder-long`).

**Уровень рассуждений (thinking).** Рассуждения включаются в pi клавишей **Shift+Tab**. Встроенная поддержка llama.cpp в pi предлагает только два уровня — `off` и `medium`, даже если модель умеет больше (например, `low`/`medium`/`xhigh`). У выгруженной модели переключатель может вовсе пропасть до её загрузки. Это ограничение pi, а не хоста: [pi#10702](https://github.com/earendil-works/pi/issues/10702), на ноябрь 2026 года открыта. Когда pi это исправит, уровни появятся после обновления pi — на ПК ничего менять не нужно.

| | opencode | pi |
|---|---|---|
| Адрес | **с** `/v1` | **без** `/v1` |
| Список моделей | вручную в конфиге | pi берёт его у хоста сам |
| Загрузить / выгрузить из программы | выбором модели | да, `/llama` |

### Любая другая программа

Подойдёт всё, что умеет работать со своим **OpenAI-совместимым** сервером (Open WebUI, Continue, Zed, библиотека `openai` для Python и т. д.):

| Поле | Значение |
|---|---|
| Base URL | `http://my-pc.tail1234.ts.net:8080/v1` |
| API key | содержимое `~/.config/locallm/api-key` |
| Model | имя из панели хоста, например `gemma` |

Пример на Python:

```python
from pathlib import Path
from openai import OpenAI

client = OpenAI(
    base_url="http://my-pc.tail1234.ts.net:8080/v1",
    api_key=Path("~/.config/locallm/api-key").expanduser().read_text().strip(),
)
reply = client.chat.completions.create(
    model="gemma",
    messages=[{"role": "user", "content": "Привет! Кто ты?"}],
)
print(reply.choices[0].message.content)
```

### Управление хостом с клиента

**Веб-панель:** откройте адрес хоста с `/ui/` на конце, например `http://my-pc.tail1234.ts.net:8080/ui/`. Панель спросит **ключ администратора** — это *другой* ключ, не ключ API; на хосте он лежит в `%LOCALAPPDATA%\locallm\admin-key.txt`. Переносится так же, как ключ API (Taildrop и тот же блок, только `admin-key` вместо `api-key` и `keys.txt`).

**Из терминала** (с переменными `H` и `KEY` из проверки выше):

```bash
# что загружено сейчас
curl -s -H "Authorization: Bearer $KEY" $H/api/status

# сменить модель (ответ придёт, когда она загрузится)
curl -s -H "Authorization: Bearer $KEY" -H 'Content-Type: application/json' -d '{"model":"gemma"}' $H/api/swap

# выгрузить модель и освободить видеокарту
curl -s -X POST -H "Authorization: Bearer $KEY" $H/api/unload
```

## Каждый день

### Значок у часов 🦙

Состояние показывает цветная точка в правом нижнем углу значка.

| Цвет точки | Что значит |
|---|---|
| ⚪ Серый | Модель не загружена, видеокарта свободна |
| 🟡 Жёлтый | Модель загружается, выгружается или ждёт видеопамять |
| 🟢 Зелёный | Модель готова |
| 🔵 Синий | Пауза |

Если навести мышь, видно модель, число запросов и занятую видеопамять. Щелчок открывает меню:

| Пункт | Что делает |
|---|---|
| **«Загрузить»** | выбрать модель или профиль |
| **«Выгрузить модель (освободить видеокарту)»** | начатые ответы дорабатывают, потом модель выгружается |
| **«Прервать запросы и выгрузить»** | обрывает ответы и выгружает модель сразу |
| **«Пауза»** / **«Продолжить»** | на паузе клиенты получают ошибку «хост на паузе», и ничего не загружается. Пауза переживает перезапуск |
| **«Открыть панель»** | веб-панель (на самом ПК — без ключа) |
| **«Открыть журнал»** / **«Открыть папку настроек»** | журнал хоста / папка с настройками |
| **«Запускать при входе в Windows»** | автозапуск вкл/выкл |
| **«Язык · Language»** | русский, English или 中文; выбор запоминается. Панель, открытая из трея, — на том же языке, а в самой панели язык меняется списком справа вверху |
| **«Выход»** | выгрузить модель и закрыть программу |

### Хочу поиграть

| Нужно | Нажать |
|---|---|
| Освободить видеокарту, но пусть клиенты снова загрузят модель, когда понадобится | **«Выгрузить модель»** |
| Освободить и держать свободной, пока сами не скажете | **«Пауза»** (потом **«Продолжить»**) |
| Освободить *прямо сейчас*, даже посреди ответа | **«Прервать запросы и выгрузить»** |

### Смена моделей

Ничего особенного делать не нужно: какую модель клиент просит, та и загрузится. Смена занимает 10–60 секунд в зависимости от размера модели.

Одна предосторожность: в течение 30 секунд после последнего обращения к модели запрос *другой* модели получает отказ `409 model_cooldown` вместо смены. Так два человека (или две программы) не выбивают модели друг друга каждые несколько секунд. Явная смена — значок, панель, `/llama` в pi или `/api/swap` — срабатывает всегда и сразу.

## Если что-то не работает

<details>
<summary><b>Первый ответ идёт очень долго</b></summary>

Модель загружается в видеопамять. Крупные модели грузятся до минуты. Смотрите на значок: жёлтый → зелёный.
</details>

<details>
<summary><b><code>401 invalid_api_key</code></b></summary>

Ключа нет или он неверный. Проверьте, что в `~/.config/locallm/api-key` ровно строка из `keys.txt` с хоста (43 символа, без пробелов). Для веб-панели нужен ключ **администратора**, а не ключ API.
</details>

<details>
<summary><b><code>404 model_not_found</code></b></summary>

Программа просит модель, которой нет на хосте. Имя должно совпадать с панелью в точности, включая регистр. В тексте ошибки — список имеющихся имён.
</details>

<details>
<summary><b><code>503 host_paused</code></b></summary>

Хост поставили на паузу. Значок → **«Продолжить»** (или та же кнопка в панели).
</details>

<details>
<summary><b><code>503 model_load_failed</code></b></summary>

Модель не загрузилась — чаще всего не влезла в видеопамять. Уменьшите `-c` (контекст) или возьмите файл поменьше. Панель → **«Журнал»** у модели покажет, что сказал llama.cpp.
</details>

<details>
<summary><b><code>409 model_cooldown</code></b></summary>

К другой модели обращались меньше 30 секунд назад. Подождите столько секунд, сколько указано в заголовке `Retry-After`, или смените модель явно (`/llama` в pi, панель, `/api/swap`).
</details>

<details>
<summary><b>Клиент совсем не видит хост</b></summary>

1. ПК включён, значок 🦙 у часов есть?
2. Оба компьютера в одном аккаунте Tailscale? (`tailscale status` на любом из них.)
3. На хосте `tailscale serve status` должен показывать `http://…:8080 → http://127.0.0.1:8080`. Если пусто — повторите шаг 6 из части 1.
4. На клиенте включите «Use Tailscale DNS settings».
</details>

<details>
<summary><b>Панель отвечает <code>403 host_not_allowed</code></b></summary>

Панель открыли по короткому имени или адресу `100.x.y.z`. Откройте по полному адресу на `….ts.net` или допишите это имя в `server.admin_hosts` в `%LOCALAPPDATA%\locallm\locallm.yaml` и перезапустите хост.
</details>

<details>
<summary><b>Хост не запускается</b></summary>

Он показывает окно с ошибкой и путём к журналу. Журнал — `%LOCALAPPDATA%\locallm\logs\host.log` (значок → **«Открыть журнал»**). Чаще всего это опечатка в файле настроек или другая программа на порту 8080.
</details>

## Обновление и удаление

**Обновить** — на ПК-хосте:

```powershell
cd $HOME\strigov-locallm
git pull
pwsh -File scripts\install.ps1
```

Скрипт остановит работающий хост, заменит программу и запустит её снова. Настройки, модели и ключи остаются как были.

**Удалить:**

```powershell
pwsh -File scripts\uninstall.ps1          # настройки и ключи остаются
pwsh -File scripts\uninstall.ps1 -Purge   # удаляет и их
```

Скрипт останавливает хост и убирает программу, ярлык, автозапуск и выдачу в tailnet. llama.cpp, модели и папку с исходниками он не трогает.

## Безопасность

- Хост слушает только `127.0.0.1` — сам по себе он не виден ни в домашней сети, ни в интернете. Наружу его выводит только `tailscale serve`, и только внутри вашего tailnet.
- Трафик внутри tailnet шифрует WireGuard, поэтому у клиентов адрес начинается с `http://`.
- Любой запрос, кроме `/health`, требует ключ API. Для панели нужен отдельный ключ администратора (на самом ПК значок открывает её одноразовым кодом).
- Ключи, тексты запросов и ответов в журнал хоста не пишутся никогда.
- Панель не принимает флаги llama.cpp, которые читают или пишут файлы, запускают инструменты или ходят в сеть. Такие флаги можно добавить только вручную, правкой `models.yaml` на ПК.
